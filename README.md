# TOKYO QUEST LOG

街のイベントを解くたびに地図が完成していく、Ebitengine製の探索RPG MVPです。

上京して間もない人が、道路だけでなく「休日に過ごせる場所」「坂や水辺がつくる地形」までゲームとして理解し、知らない街へ出かけるきっかけを得る、という仮説を検証します。

## 現在遊べる内容

- 1つのモデル地区を自由に移動
- マップ上の3イベントを探索
- 街に関する問いへ回答
- クリアごとに以下の地図レイヤーを復元
  - 移動：駅、主要道路、街のつながり
  - 生活：図書館、公園、文化施設、休憩場所
  - 地形：池、台地、坂、高低差
- 全イベント後に「自分が理解した街」の完成画面を表示

現在の地図と施設はゲームループ検証用のサンプルです。実在施設の正確な位置や、リアルタイムの案内を提供するものではありません。

## 起動方法

Go 1.24以降が必要です。

```powershell
go run .
```

この環境ではGoがPATHに入っていないため、次でも起動できます。

```powershell
& 'C:\Program Files\Go\bin\go.exe' run .
```

ビルド済みの `tokyo-quest-log.exe` を直接起動することもできます。

## 操作

| キー | 操作 |
|---|---|
| `WASD` / 矢印 | 移動 |
| `Space` / `Enter` | イベントを調べる |
| `1` `2` `3` | 回答を選ぶ |
| `Esc` | イベントを閉じる |
| `R` | 進行状況をリセット |

## テスト

```powershell
go test ./...
```

ゲームロジックは描画から分離し、以下を自動テストしています。

- 不正解ではレイヤーが解放されない
- 正解すると対応レイヤーが解放される
- 全イベント達成で完成状態になる
- リセットで初期状態へ戻る

## オープンデータ接続方針

MVPでは、次のデータ種別がゲームルールとして機能するかを先に検証します。

| レイヤー | 接続候補 | ゲームでの用途 |
|---|---|---|
| 移動 | 駅、道路、公共交通 | 経路と街の入口を生成 |
| 生活 | 公共施設、公園、文化施設 | 居場所探索イベントを生成 |
| 地形 | 標高、河川・水辺 | 坂、水辺、低地の推理イベントを生成 |

実データ接続時は、データセット名、提供者、取得日、ライセンス、更新日を画面と配布物に明記します。取得したデータはアプリ用の共通スキーマへ変換し、ゲーム本体が自治体ごとのCSV形式に直接依存しないようにします。

## 次に検証すること

1. 上京1〜5年程度の人にプレイしてもらう
2. プレイ前後で、街の特徴を説明できる度合いを比較する
3. 「この地域へ行ってみたいか」を5段階で測る
4. イベントがクイズではなく、地図を読む判断になっているか観察する
5. 効果が確認できてから、1地区の実データを接続する

## 構成

- `main.go`：アプリ起動
- `game.go`：入力・描画・画面遷移
- `model.go`：イベント、レイヤー、進行状態
- `model_test.go`：進行ロジックのテスト
